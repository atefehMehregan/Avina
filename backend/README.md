# سرویس حساب کاربری آوینا

API احراز هویت برای فروشگاه آوینا. این سرویس جدا از سایت ایستا اجرا می‌شود؛
GitHub Pages فقط فایل ایستا می‌دهد و نمی‌تواند بک‌اند اجرا کند.

## چرا این انتخاب‌ها

| موضوع | انتخاب | دلیل |
|---|---|---|
| زبان | Node.js + Express | فرانت هم جاوااسکریپت ساده است؛ یک زبان برای کل پروژه |
| پایگاه داده | SQLite (better-sqlite3) | بدون سرور جدا، فایل‌محور، سریع. کوئری‌ها استاندارد SQL‌اند و مهاجرت به PostgreSQL بعدا کار سختی نیست |
| رمز | Argon2id | توصیه فعلی OWASP؛ کتابخانه رسمی، نه پیاده‌سازی دست‌ساز |
| نشست | توکن تصادفی + کوکی HttpOnly | برخلاف JWT، «خروج» واقعا نشست را می‌بندد — برای حساب خرید لازم است |

## راه‌اندازی محلی

```bash
cd backend
npm install
cp .env.example .env      # مقدارها را در .env تنظیم کنید
npm run migrate           # ساخت جدول‌ها
npm start                 # پیش‌فرض روی پورت ۴۰۰۰
```

سپس سایت را از ریشه پروژه سرو کنید (مثلا `python3 -m http.server 8090`)
و در `index.html` مقدار `<meta name="avina-api-base">` را خالی بگذارید؛
`JS/config.js` روی localhost خودش سرور محلی را پیدا می‌کند.

## آزمون

```bash
npm start                      # در یک ترمینال
node tests/auth.test.mjs       # در ترمینال دیگر
```

آزمون کاربر آزمایشی با ایمیل تصادفی می‌سازد؛ هیچ اعتبارنامه‌ای در مخزن نیست.

## مسیرهای API

| متد | مسیر | کار |
|---|---|---|
| GET | `/api/health` | زنده بودن سرویس |
| POST | `/api/auth/register` | ثبت‌نام؛ ۲۰۱ موفق، ۴۲۲ ورودی نامعتبر، ۴۰۹ تکراری |
| POST | `/api/auth/login` | ورود با ایمیل یا موبایل؛ ۲۰۰ / ۴۰۱ / ۴۲۹ |
| POST | `/api/auth/logout` | خروج (نیازمند هدر `X-CSRF-Token`) |
| POST | `/api/auth/logout-all` | خروج از همه دستگاه‌ها |
| GET | `/api/auth/me` | کاربر جاری؛ ۴۰۱ اگر وارد نشده باشد |

پاسخ‌ها JSON ساختاریافته‌اند و هرگز `password_hash` یا فیلد داخلی ندارند.

## امنیت

- رمز با **Argon2id** هش می‌شود؛ متن رمز هیچ‌جا ذخیره یا لاگ نمی‌شود.
- توکن نشست فقط به شکل **SHA-256** در دیتابیس است.
- کوکی نشست **HttpOnly** است؛ جاوااسکریپت صفحه به آن دسترسی ندارد.
- **CSRF**: الگوی double-submit با هدر `X-CSRF-Token` برای درخواست‌های تغییردهنده.
- **CORS**: فقط مبداهای فهرست‌شده در `ALLOWED_ORIGINS`. هرگز `*`.
- **محدودیت نرخ**: قفل موقت پس از چند ورود ناموفق، بر پایه شناسه و آی‌پی.
- همه کوئری‌ها پارامتری‌اند (در برابر SQL injection).
- فقط فیلدهای مشخص از بدنه خوانده می‌شود (در برابر mass assignment).
- پیام خطای ورود مبهم است تا نشود فهمید کدام حساب وجود دارد.
- جزئیات خطای داخلی به کاربر نمی‌رسد؛ فقط یک کد ارجاع.

## استقرار روی اینترنت

سرویس باید جایی اجرا شود که Node.js می‌دهد — مثلا **لیارا**، **آروان**،
Render یا Fly.io. بعد از استقرار:

1. در محیط سرویس این‌ها را تنظیم کنید:
   ```
   NODE_ENV=production
   ALLOWED_ORIGINS=https://atefehmehregan.github.io
   DATABASE_FILE=/var/data/avina.sqlite     # مسیر ماندگار، نه داخل کانتینر
   ```
2. `npm run migrate` یک بار اجرا شود.
3. در `index.html` مقدار متا را پر کنید:
   ```html
   <meta name="avina-api-base" content="https://api.example.com" />
   ```
4. سرویس حتما روی **HTTPS** باشد؛ در حالت production کوکی با
   `Secure` و `SameSite=None` فرستاده می‌شود و روی http کار نمی‌کند.

## گام بعدی (سفارش و پرداخت)

جدول‌های `addresses`، `orders`، `order_items` و `payments` از همین حالا در
`schema.sql` ساخته شده‌اند تا اضافه کردن سبد خرید، ثبت سفارش و درگاه
پرداخت نیازی به بازنویسی ساختار نداشته باشد.
