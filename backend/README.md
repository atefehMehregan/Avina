# سرویس حساب کاربری آوینا

API احراز هویت برای فروشگاه آوینا. این سرویس جدا از سایت ایستا اجرا می‌شود؛
GitHub Pages فقط فایل ایستا می‌دهد و نمی‌تواند بک‌اند اجرا کند.

## چرا این انتخاب‌ها

| موضوع | انتخاب | دلیل |
|---|---|---|
| زبان | Node.js + Express | فرانت هم جاوااسکریپت ساده است؛ یک زبان برای کل پروژه |
| پایگاه داده | **PostgreSQL** با `pg` | روی همه ارائه‌دهنده‌های ابری پلن رایگان دارد (Supabase، Neon، Railway)، پس دیگر به دیسک ماندگارِ پولی نیاز نیست |
| استخر اتصال | `pg.Pool` | برای هر کوئری اتصال تازه باز نمی‌شود |
| رمز | Argon2id | توصیه فعلی OWASP؛ کتابخانه رسمی، نه پیاده‌سازی دست‌ساز |
| نشست | توکن تصادفی + کوکی HttpOnly | برخلاف JWT، «خروج» واقعا نشست را می‌بندد |

## راه‌اندازی محلی

```bash
cd backend
npm install
cp .env.example .env      # DATABASE_URL را پر کنید
npm start                 # جدول‌ها هنگام بالا آمدن ساخته می‌شوند
```

اگر PostgreSQL محلی ندارید، برای اجرای آزمون‌ها نیازی هم نیست — پایین را ببینید.

سپس سایت را از ریشه پروژه سرو کنید (مثلا `python3 -m http.server 8090`).
`JS/config.js` روی localhost خودش سرور محلی را پیدا می‌کند.

## آزمون

```bash
npm test
```

آزمون سرور را خودش بالا می‌آورد و روی یک پایگاه داده‌ی **جدا** اجرا می‌شود:

- پیش‌فرض **PGlite** — همان PostgreSQL، کامپایل‌شده به WASM، در یک پوشه موقت.
  چیزی نصب نمی‌خواهد و به هیچ پایگاه داده‌ی بیرونی دست نمی‌زند. فقط
  وابستگی توسعه است و در تولید بار نمی‌شود.
- اگر `TEST_DATABASE_URL` بدهید، روی همان PostgreSQL اجرا می‌شود.

آزمون هرگز `DATABASE_URL` تولید را برنمی‌دارد؛ باید صریح `TEST_DATABASE_URL` بدهید.

## مسیرهای API

| متد | مسیر | کار |
|---|---|---|
| GET | `/api/health` | زنده بودن سرویس |
| POST | `/api/auth/register` | ثبت‌نام؛ ۲۰۱ موفق، ۴۲۲ ورودی نامعتبر، ۴۰۹ تکراری |
| POST | `/api/auth/login` | ورود با ایمیل یا موبایل؛ ۲۰۰ / ۴۰۱ / ۴۲۹ |
| POST | `/api/auth/logout` | خروج (نیازمند هدر `X-CSRF-Token`) |
| POST | `/api/auth/logout-all` | خروج از همه دستگاه‌ها |
| GET | `/api/auth/me` | کاربر جاری؛ ۴۰۱ اگر وارد نشده باشد |

قرارداد API با مهاجرت به PostgreSQL تغییر نکرد؛ فرانت نمی‌داند زیرش چه
پایگاه داده‌ای است.

## امنیت

- رمز با **Argon2id** هش می‌شود؛ متن رمز هیچ‌جا ذخیره یا لاگ نمی‌شود.
- توکن نشست فقط به شکل **SHA-256** در دیتابیس است.
- کوکی نشست **HttpOnly** است؛ جاوااسکریپت صفحه به آن دسترسی ندارد.
- **CSRF**: الگوی double-submit با هدر `X-CSRF-Token`.
- **CORS**: فقط مبداهای `ALLOWED_ORIGINS`. هرگز `*`.
- **محدودیت نرخ**: قفل موقت پس از چند ورود ناموفق، بر پایه شناسه و آی‌پی.
- همه کوئری‌ها پارامتری‌اند (`$1`, `$2` ...) — در برابر SQL injection.
- فقط فیلدهای مشخص از بدنه خوانده می‌شود (در برابر mass assignment).
- پیام خطای ورود مبهم است تا نشود فهمید کدام حساب وجود دارد.
- جزئیات خطای داخلی به کاربر نمی‌رسد؛ فقط یک کد ارجاع.

## استقرار

سرویس روی هر میزبان Node.js اجرا می‌شود (Render، Railway، Fly.io، لیارا) و
پایگاه داده جدا و مدیریت‌شده است.

**مهم:** با PostgreSQL دیگر به **دیسک ماندگار** نیازی نیست، پس محدودیت
«دیسک فقط روی پلن پولی» برطرف شده است.

متغیرهای محیطی تولید:

```
NODE_ENV=production
DATABASE_URL=postgresql://...        # از ارائه‌دهنده پایگاه داده
ALLOWED_ORIGINS=https://atefehmehregan.github.io
```

نکته‌های عملی:

- **Supabase**: رشته اتصال را از Connection string → URI بردارید. برای
  سرویس‌های بدون IPv6 حالت **pooler** (پورت ۶۵۴۳) را انتخاب کنید و
  `DATABASE_POOL_MAX` را کم بگذارید (مثلا ۵)، چون pooler سهمیه دارد.
- **SSL**: پیش‌فرض تولید روشن و با بررسی گواهی است. فقط اگر ارائه‌دهنده
  گواهی خودامضا می‌دهد `DATABASE_SSL=no-verify` بگذارید.
- جدول‌ها هنگام بالا آمدن سرویس ساخته می‌شوند؛ دستور جداگانه لازم نیست.
  اگر خواستید وضعیت را ببینید: `npm run migrate`.
- سرویس حتما روی **HTTPS** باشد؛ کوکی با `Secure` و `SameSite=None`
  فرستاده می‌شود و روی http کار نمی‌کند.

## گام بعدی (سفارش و پرداخت)

جدول‌های `addresses`، `orders`، `order_items` و `payments` از همین حالا در
`schema.sql` ساخته شده‌اند تا اضافه کردن سبد خرید، ثبت سفارش و درگاه
پرداخت نیازی به بازنویسی ساختار نداشته باشد. مبلغ‌ها `BIGINT` تومان‌اند.
